# Outline and Writing Sequence

## Default order

When the user wants a thesis rather than a fragment, use this order:

1. clarify the thesis storyline
2. build the three-level outline
3. assign responsibilities to each chapter
4. confirm body page count
5. write only the requested chapter range
6. place figures, tables, and placeholders where needed
7. write abstract and conclusion after the body is stable
8. compile and clean up

Do not finalize the abstract before the main body is stable.

## Decide the thesis type first

Do not force the same skeleton onto every thesis. First decide whether the work is mainly:

- research-oriented
- project-oriented
- hybrid

This decision affects the role of Chapters 2 through 5.

## Common six-chapter backbone

### Chapter 1: Introduction

Typical responsibilities:

- background and significance
- state of the art
- gap or challenge
- what this thesis actually does
- thesis structure

### Chapter 2: Foundations / Related Work / Requirements and Constraints

Typical responsibilities:

- theoretical or technical background
- related work
- requirement analysis
- constraints that shape later decisions

### Chapter 3: Method / Platform / Overall Solution

Typical responsibilities:

- overall architecture
- platform or environment
- module relationships
- technical route
- why the arrangement is reasonable

### Chapter 4: Detailed Design / Implementation / Core Results

Typical responsibilities:

- the real technical work completed
- key design choices
- implementation details
- transfer from earlier constraints into realization

### Chapter 5: Testing / Validation / Result Discussion

Typical responsibilities:

- test environment
- test method
- test results
- analysis and optimization loop

### Chapter 6: Conclusion and Future Work

Typical responsibilities:

- what was completed
- what value it has
- what remains limited
- what can be improved later

## Subsection logic

A stable subsection pattern usually follows:

- what the problem or object is
- why it is difficult or constrained
- how existing methods handle it
- how this thesis handles it
- what support or conclusion it provides

## Figure distribution by chapter

- Introduction: comparison figures, state-of-the-art summaries, comparison tables
- Foundations / requirements: principle figures, classification figures, summary tables
- Overall solution: architecture figures, composition figures, process diagrams
- Detailed design / implementation: structure figures, timing diagrams, parameter tables
- Testing / validation: test-flow figures, result plots, screenshots, summary tables

Do not force a figure into every subsection.
