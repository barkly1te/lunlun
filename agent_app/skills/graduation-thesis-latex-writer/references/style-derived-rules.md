# Style Rules Derived from the User's Thesis Preferences

## Core principle

A thesis sounds academic not because it is long, but because the information is organized into a verifiable and progressive line of reasoning.

Priority order:

1. chapter function
2. paragraph progression
3. terminology discipline
4. sentence quality
5. final smoothness

## Tone

- precise
- sober
- information-dense
- low on slogans and filler

Avoid low-information claims unless they are immediately grounded in technical detail.

## Sentence rule

Each sentence should ideally do one clear job:

- define
- limit
- explain
- compare
- infer
- conclude

If a sentence expresses attitude without information, rewrite it.

## Paragraph rule

Default paragraph structure:

`problem -> explanation -> conclusion`

Do not stack facts without a controlling point.

## Chapter rule

Each chapter and section should answer a specific question in the thesis:

- Abstract: background -> problem -> work -> result -> conclusion
- Introduction: background -> state of the art -> gap -> work of this thesis
- Design or method: solution -> reason -> implementation path -> justification
- Testing or validation: conditions -> method -> result -> what the result means

If a section cannot carry that function, fix the structure before polishing the prose.

## Revision order

When revising existing text, default to:

1. structure judgment
2. key problems
3. paragraph-level or line-level comments
4. directly replaceable revision
5. explanation of why the revision is better

## Boundary honesty

- Write only within the real scope of the work.
- Do not present unfinished work as completed work.
- Use "validation" or "analysis" for validated claims rather than inflating them into breakthroughs.

## Terminology and abbreviations

- Expand abbreviations only when they are conventional and reused later.
- Do not force English terms onto concepts that do not need them.
- Once an abbreviation has been formally expanded, do not treat it as first appearance again.

## Figure and table style

- Explain a figure or table once, not redundantly before and after.
- Embed the caption and explanation into the thesis flow.
- At the end of a subsection, give a concrete figure or table suggestion if it helps.

## De-AI-ing rule

De-AI-ing does not mean making the text vague. It means:

- remove template connectors that appear too often
- stop repeating the same point in slightly different wording
- replace generic claims with concrete constraints and relationships
- let the sentence itself carry the conclusion
